# 学习笔记规则

本目录保存导师答疑、用户知识疑问、Assignment 作答、阶段复盘问答和用户明确指定的复习材料。它是学习证据的一部分，不是任务流水、协作记录或临时聊天记录；所有笔记必须纳入 Git 追踪，避免阶段学习成果丢失。

## 1. 文件命名规范

- 每个阶段原则上保留一个主文件：`YYYYMMDD-PhaseX-学习笔记.md`，例如 `20260826-Phase3-学习笔记.md`。
- `X` 使用项目阶段编号；同一阶段后续问题优先更新该阶段主文件，不随意创建碎片文件。
- 只有内容体量或用户明确要求需要拆分时，才创建附属文件，并在主文件中建立链接。
- 文件创建或更新后必须确认 Git 已追踪：`git ls-files docs/learning-notes/` 能看到对应路径；若本地 `.git/info/exclude` 仍忽略目录，使用 `git add -f docs/learning-notes/<file>` 纳入追踪。

## 2. 记录规则

只有用户明确要求记录某个问题、Assignment 作答、导师答疑或阶段复盘内容时，才触发学习笔记。仅提出问题或发生对话不构成记录授权。触发后 Agent 必须：

1. 先读取本规则和当前阶段的权威文档；
2. 定位对应阶段学习笔记；
3. 对用户问题进行原文记录，不能只写 Agent 的概括；
4. 回答后记录证据、结论、未决项和是否需要复习；
5. 将笔记写入本目录并纳入 Git 追踪；
6. 在下一次正常阶段日志更新时，按用户的记录要求纳入必要的答疑结论；不因答疑单独创建一轮开发日志。

用户原话、疑惑、阻塞点和 Assignment 作答不得被改写成“用户已理解”。用户没有回答的练习必须标记为 `待练习`。

任务指令、规划偏好、对 Agent 工作方式的纠正、进度确认、普通执行交接和命令/测试输出，不因对话发生而自动进入学习笔记或开发日志。无法判断时默认不记录。

## 3. 事实口径

笔记必须区分以下状态，不得把计划写成实现：

- `CONFIRMED`：有当前代码、测试、运行输出、ADR 或权威文档支持；
- `PLANNED`：已批准并排入路线，但尚未产生实现/出口证据；
- `INFERRED`：根据已命名证据推导，必须说明推理和不确定性；
- `UNRESOLVED`：证据不足，必须保留问题，不能猜测；
- `CONFLICTED`：权威来源不一致，先记录冲突，不给出伪确定结论。

笔记回答必须以当前 `PRD`、`ARCHITECTURE`、`DESIGN`、`SPEC`、`PLAN`、`ROADMAP`、ADR、代码和真实测试为准。阶段路线以最新批准的纠偏方案为准；历史日志只说明当时发生过什么，不得覆盖当前事实。

实验室代码、Mock、Fixture、准备包或协议实验不能写成真实 ERP 业务已部署。没有客户采用、生产部署、效率收益或模型质量证据时，不得编造相关结论。

## 4. 回答规范

- 先用大白话回答，再补技术细节；先说明用户能看到什么和数据怎样流动。
- 明确回答“当前已实现什么、尚未实现什么、计划在哪个阶段、证据在哪里”。
- 纠正旧口径时，直接覆盖已经失效的回答，不保留会干扰后续学习的旧答案副本；原始用户问题和用户原话仍必须保留。
- 对外面试表达默认先讲业务问题、实际价值、已完成链路和生产级工程能力，不主动暴露仓库定位、学习属性或实验分层；内部事实只作为 Agent 的校验依据，不在答案中额外展开说明。
- “按生产级要求设计”“面向生产落地”必须有权限、审计、校验、回退等证据支撑；不得把设计目标说成已生产部署、已有客户或已验证收益。
- 使用项目统一术语：Agent Run、Scope、Typed Tool Gateway、Proposed Action、Approval Decision、Execution Receipt、Reconciliation 等。
- 不把模型的解释能力说成业务决策能力，不把 Tool Gateway 说成模型已经自主 Tool Calling，不把 FTS5 说成完整长期记忆。
- 涉及身份、权限、金额、状态、幂等、ERP 写入、安全或成本时，必须说明确定性门禁和失败路径。
- 事实不足时写明 `UNRESOLVED`，并指出需要什么证据；不能用流畅表达掩盖未知。

## 5. 回答整体结构

每个阶段学习笔记的答疑轮次按以下结构组织：

```markdown
## 本轮用户提问原文
> 逐字记录用户问题

## 1. 问题标题
### 对外面试回答
先给业务价值、用户结果和当前已完成链路。

### 大白话解释
说明业务问题、用户看到的结果和数据流。

### 当前证据与边界
区分 CONFIRMED / PLANNED / UNRESOLVED，并链接文件、代码或测试。

### 技术细节、风险与面试表达
解释架构、失败路径、取舍和不能夸大的地方。
```

五个以上的问题必须逐题回答，不合并成一段泛泛总结。每轮末尾补充：

- 本轮事实来源；
- 用户 Assignment/疑惑的状态；
- 需要复习的内容；
- 未决问题和下一步证据。

## 6. Git 保留规则

学习笔记属于项目学习证据。Agent 更新或新建文件后必须检查：

```bash
git add -f docs/learning-notes/<changed-file>
git ls-files docs/learning-notes/
```

本规则不授权 Agent 自动 commit 或远程 push；提交和推送仍遵循项目现有授权边界。但任何学习笔记都不得继续停留在 Git 不追踪状态。
