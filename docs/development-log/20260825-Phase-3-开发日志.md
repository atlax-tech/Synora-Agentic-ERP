### 本轮任务大白话讲解
系统试着让模型把"干巴巴的分析报告"翻译成好懂的话，但有个铁规矩：模型只能换说法，不能自己发明数字或结论。刚才真模型试了一次，它想多加几个数字，被系统拦下来、自动退回用确定性文案——宁可不用模型解释，也不让模型碰数字。

### 面试官可能追问的技术细节以及如何回答
- 问：为什么校验只查数字？答：金额/数量/阈值全部是数字，模型编造任何数字都会改变业务结论；数字集合校验是机械、可测试的硬门禁，比语义校验可靠。
- 问：回退频繁是否浪费 token？答：本次验证 in=523 out=654 成本约 ¥0.0005；即使回退也完成了一次真实模型路径的端到端验证（提示词→调用→校验→回退），证据可复跑；生产接入可先试跑再看是否值得。
- 问：服务商不遵守 max_tokens 怎么办？答：代码在请求中发送 max_tokens=256，但中转服务可能忽略；成本由调用次数与输入长度控制，超预算由用户侧 API 限额兜底，并记录实际 token 用量。

- 问：为什么空仓库不发送 `warehouse: null`？答：Frappe 表单参数会经过序列化，省略可选字段能稳定落到 API 的默认 `None` 分支，同时保留服务端范围校验作为最终门禁。

- 问：为什么列表要防御空 `goal`？答：历史数据或兼容数据可能没有目标，展示层不应因可空字段调用 `.length` 崩溃；空字符串只影响展示，不改变权限或状态。
