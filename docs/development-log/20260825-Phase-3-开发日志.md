### 面试官可能追问的技术细节以及如何回答
- 问：为什么 run_state 和 status 分两个字段？答：status 是 Phase 2 capability 生命周期（ACTIVE/REVOKED），run_state 是 SPEC §8.1 业务状态机；合并会混淆"凭据有效性"与"业务进度"两种语义。
- 问：空白 goal 为什么单独校验？答：bounded_text 只拒绝空字符串，全空格目标无业务意义且 PRD 要求"空目标"明确处理，因此 strip 后拒绝而非自动猜测。
- 问：取消为什么同时撤销 capability？答：已取消的分析不应继续执行工具调用；capability 失效使任何未完成请求在 resolve_run 阶段被拒，状态机与凭据双保险。

### 面试官可能追问的技术细节以及如何回答
- 问：为什么指纹同步要用字符串替换而不是重写 JSON？答：manifest 采用 compact 逐字段格式，整树重写会产生无意义的大 diff 并破坏可读性；按 path 定位替换 sha256 保持最小变更。
- 问：drift 检查为什么区分 managed-content 与 source-index？答：managed_files 记录托管文档指纹，source_index 记录事实源的修订定位；两者一致才证明"文档没被偷改"。
- 问：为什么术语表同时写进 DESIGN 和 SPEC？答：DESIGN 承载产品文案术语权威，SPEC §8.1 记录状态机文案映射，避免实现时状态显示与术语表漂移。
