### 10. 面试官可能追问的技术细节以及如何回答

1. 为什么要先写 `STARTED` reservation 再调用 ERP controller？——ERP 写入和 HTTP 响应不是同一个事实；先持久化 reservation 能让崩溃后的请求进入可对账状态，避免第二次请求盲目重写。
2. 为什么 writer 不接受客户端 payload？——批准的是服务器保存的不可变 action digest；重新接收 payload 会允许用户在批准后替换 item、qty 或 scope，破坏审批与执行的一致性。
3. 为什么成功必须 read-back 后才能写 Receipt？——controller 返回或 HTTP 200 只能说明调用结束，Receipt 必须证明 ERP 里存在 Draft 且 critical fields 与批准内容一致。
4. 同 key replay 为什么还要重新检查 read permission？——旧结果不能绕过当前权限；无权用户既不能读取历史 MR，也不能从 replay 响应推断其内容。
5. validation 失败为什么 Action 走 `EXPIRED` 而不是复活？——这次批准已经消耗且 execution evidence 已失败；任何新业务尝试必须重新提议、重新评估和重新批准。`待阶段答疑`
