### 10. 面试官可能追问的技术细节以及如何回答

1. 为什么 approval actor 不能由请求体传入？——请求体和模型输出都不可信；Frappe session 是当前登录事实，Run initiator 和 effective permission 再绑定业务范围，客户端只能提交决定和已展示的 digest。
2. 为什么 scope 失败后 permission/deterministic 记录 UNKNOWN，而不是继续查？——继续查会把对象存在性和权限差异变成信息 oracle；UNKNOWN 明确表示不能授权，策略结果只能拒绝。
3. 为什么 active Workflow 不能在 Runtime 自己解释？——ERPNext Workflow 是权威配置，条件可能随版本/脚本变化；复制表达式会产生第二套审批事实，未完成新 mapping 就采用更严格规则并 fail closed。
4. 如何防止审批后撤权或出现重复 MR？——pre-execute 在同一锁定窗口重新读取当前 session/Run/DocPerm、Item/Supplier、MR/PO open state、policy/approval/digest/idempotency；任意漂移返回冲突并禁止进入 writer。
5. 为什么 `APPROVED` 仍不代表 ERP 写成功？——批准只证明某个 digest 在某个 snapshot 下获准；真正写入还要经过官方 controller、幂等 reservation、读回关键字段和 Receipt。`待阶段答疑`
