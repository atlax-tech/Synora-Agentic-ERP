### 9. 本轮任务大白话讲解

这一轮把四种“找资料”的方式放到同一套资料和同一套权限条件下比较。最初发现一个真实问题：向量检索会把“公开政策但当前只能看内部资料”的问题，语义上匹配到允许查看的内部资料；这不是越权，却不能被错误地记成失败。修复后，评测明确区分“必须完全没结果”和“禁止的那份资料不能出现”，并且任何真正越权都会让整路实验失格。结果四路都能找到固定正例，但向量层没有质量收益，反而需要大模型文件和更多内存，所以业务继续使用速度快、可重建的 FTS5。

### 10. 面试官可能追问的技术细节以及如何回答

- 问：为什么不把所有负例都要求零命中？答：词法检索的 no-hit 不能直接泛化到语义检索；跨范式安全要求是禁止目标不可见、返回结果仍满足 scope/version，语义替代必须单独记录。
- 问：Hybrid 为什么用 RRF 而不是相加 BM25 与 cosine？答：两者分数尺度不同，直接相加没有可解释校准；RRF 只融合排名，确定性且不改变 provenance。
- 问：为什么向量实验没有进入业务路径？答：固定正例指标与 FTS5 相同，模型/内存/延迟成本更高；根据 Adoption Card 和用户批准门，保持 LAB_ONLY/FTS5 baseline。
- 问：模型能否决定权限或生成引用？答：不能。权限与版本在服务端过滤，reranker 只返回排序分数，chunk ID/digest/citation 全来自原始 T04 chunk。
- 问：为什么第一次 comparison 不能直接提交？答：真实 negative correctness 只有 0.75 且 harness 把 arm 标成 PASS，存在证据矛盾；按故障规则停止、记录、让 C2C 判定根因后再加回归修复。以上均为待练习。

### 10. 面试官可能追问的技术细节以及如何回答

- 问：为什么 scope 要求所有字段精确相等？答：可选字段代表更窄边界，省略不能被解释成“全部可见”，否则会产生跨仓库或跨 Run 的隐式扩大。
- 问：为什么候选不能直接召回？答：候选正文来源不等于业务事实，必须先经过对应权限主体审核；召回门只接受 `APPROVED`、未过期且精确范围匹配的记录。
- 问：为什么纠正要新建版本？答：原记录需要保留审计和可追溯关系；新内容先是候选，旧内容停止召回，不能用原地编辑掩盖历史。
- 问：为什么不在这里设统一 TTL？答：产品只要求审核时的 Episodic 到期和来源版本约束，没有批准统一数值；擅自设 TTL 会把未经证实的策略写进安全边界。以上问题均为待练习。
