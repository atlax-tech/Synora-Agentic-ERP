### 9. 本轮任务大白话讲解

原生 Tool Calling 和前面的 prompt ReAct 不同：模型不是在文本里“猜一个动作”，而是返回带 id 的 function call。Runtime 执行只读工具后，要把同一个 id、工具名和有界摘要作为 `tool` 消息送回 provider。我们先把这条消息链在离线 scripted provider 上锁住，真实 API 和权限仍由后续阶段门禁控制。

### 10. 面试官可能追问的技术细节以及如何回答

- 为什么同一响应里同时有 final text 和 tool call 时以 tool call 为准？因为 tool call 是 provider 的结构化动作，文本可能只是未验证的附带内容；先执行动作并重新观察，避免把未验证文本当业务结论。
- 为什么允许 provider call id 进入消息但不把它当业务事实？id 只用于协议配对和 Trace 关联，不代表 ERP 单据或授权状态。
- 为什么 native adapter 仍要重复本地 allowlist/schema 校验？provider function definitions 只是提示和格式约束，不是权限边界；模型可以返回未列出的名称或非法 JSON，Runtime 必须 fail closed。
