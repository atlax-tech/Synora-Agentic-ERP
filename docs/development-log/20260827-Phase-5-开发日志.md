- LangGraph 版本漂移：只锁定经过 Python 3.14 Spike 的精确版本和 lockfile，保持 lab-only；未通过安全/恢复矩阵前不进 Runtime。
- SQLite 单实例边界：启用 WAL/foreign keys/busy timeout/0600，但尚未声称生产扩展能力。
- 本轮未触碰用户维护文件和秘密；真实调用账本、cancel/expiry 先 CAS 再通知 Runtime 的顺序留给 P5.3/P5.4。

### 9. 本轮任务大白话讲解

以前 Agent 请求结束，运行进度就只在内存里；现在给每个只读长任务一张严格的“进度卡”：卡上有版本、步骤顺序、依赖、完成摘要和等待用户回答的位置。Runtime 重启只能从这张卡的安全点继续，卡里没有 ERP 事实、用户密码或 capability。Frappe 仍是 Run、权限和有效期的唯一权威，下一轮会把每次只读工具调用也登记到 Frappe 账本，保证崩溃恢复不重复进入 ERP Handler。

本轮最重要的文件：

- `services/agent_runtime/src/agent_runtime/workflow/contracts.py`：严格计划/状态/澄清契约；
- `services/agent_runtime/src/agent_runtime/workflow/checkpoint.py`：SQLite checkpoint/CAS/lease；
- `services/agent_runtime/src/agent_runtime/workflow/runtime.py`：Runtime 工作流入口和恢复语义。

### 10. 面试官可能追问的技术细节以及如何回答

- 为什么 checkpoint 不能代表 ERP 状态？答：它只记录 Runtime 是否走到某个编排节点，工具事实和授权每次都要回到 Frappe/Gateway 重查。
- 为什么 completed step 要不可变？答：恢复和重规划只能替换尚未开始的节点，否则同一 run 的证据会被悄悄改写，无法判断是否重复调用。
- 为什么 LangGraph 先留在 lab？答：Python 3.14 Spike 已通过，但主线采用还必须通过与手写引擎同任务的安全、恢复、不重放、Trace 和运维比较。
