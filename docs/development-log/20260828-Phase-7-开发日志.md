### 7. 风险预估与规避

- 上下文成本失控：`3×3=P1`；通过无代码默认预算、每轮 estimate、固定压缩和实际 usage 后验拒绝规避。当前无已知 P1 未关闭问题。
- 压缩删除安全条件：`3×4=P1`；安全 Prompt 是 required system message，最新 Observation/digest/tool schema 保留；mandatory 最小上下文仍超限时 fail closed。
- 估算与真实 tokenizer 不一致：显式使用 `estimated_input_units`，Provider usage 单独记录为 `actual_prompt_tokens`；不把字节数写成真实 token。
- 调用方无序输入导致复现漂移：工具、Skill、Reference、Observation 按稳定键排序；canonical JSON 固定对象键顺序。
- 本轮未改变 Gateway、policy、Executor、ERP 写能力；P7.2b 才处理 Runtime/Frappe event wire 与持久化。

### 9. 本轮任务大白话讲解

以前每次调查都会把旧 Observation 原文继续累加，步骤多时 Provider 输入会线性变大。本轮加了一个固定的“上下文装配工”：先收集当前任务需要的东西，再只选择服务端允许的内容，把 Goal 和 ERP 观察标成不可信数据，最后按固定顺序压缩旧记录。系统安全规则不会被压缩掉；如果连最小安全上下文都装不进用户明确给的预算，就停止，不调用模型。数据流是：调用方提供 Goal/工具/观察 → ContextBuilder 生成两条 Provider message 和有效 tool schema → Provider 返回 usage → 后续 Runtime 再决定是否接受模型动作。

### 10. 面试官可能追问的技术细节以及如何回答

- 为什么要分 estimate 和 actual token？答：调用前只有本地可计算的 UTF-8 保守上界，不能冒充 Provider tokenizer；调用后才有 `prompt_tokens` 事实，若实际超过配置要保留 usage 并拒绝动作。状态：待练习。
- 压缩时为什么不直接提高预算？答：预算是用户明确配置的成本边界；应先按规定顺序删未选 catalog、未触发参考、压缩旧 Observation，mandatory 仍超限就 fail closed，不能用更大预算掩盖上下文设计问题。状态：待练习。
- 如何证明恶意 Observation 没有改变安全边界？答：system message 来自 Registry 的 required boundary，Goal/Observation 只在 user canonical JSON 的 `UNTRUSTED` 字段；effective tools 从调用方 allowlist 校验，内容不能创建新 schema。状态：待练习。

### 9. 本轮任务大白话讲解

以前两个业务入口各自把一段 system prompt 写在代码里，改一个地方容易忘另一个地方，也无法证明 A/B 只改了调查顺序。本轮把规则收进一个有版本的登记册：安全边界、失败时怎么停、最终结果怎么写，三层共同固定；只有“下一步先查什么”允许做 A/B。模型只能看到这些指令，授权和工具能力仍由现有 Gateway/allowlist 决定。数据流是：业务入口选择已登记 profile → Runtime 组合四层 → Provider 收到 system/user message → 现有 typed parser、证据和工具门禁继续校验。

### 10. 面试官可能追问的技术细节以及如何回答

- 为什么 Prompt hash 不能直接用普通 `dict` 转字符串？答：普通表示可能受插入顺序和序列化细节影响；这里使用固定层顺序、`sort_keys`、稳定 separators 和 UTF-8 canonical JSON，再做 SHA-256，才能让同一 profile 可复现。
- 如何证明 A/B 是单变量实验？答：比较 A/B 的非 decision canonical bytes 和 boundary/recovery/output 层 hash；只有 decision 层 hash、profile 总 hash 可以不同，任务、工具、模型和安全层由后续固定评测保持一致。状态：待练习。
- Prompt 为什么不能授予模型权限？答：Prompt 是不可信指令输入，真正的能力来自调用方 allowlist、typed Gateway 和服务端权限；即使文本诱导写入，也没有对应 tool schema，Gateway 仍会拒绝。状态：待练习。
